## 改了什麼
移除 Worker 啟動判斷中寫死的舊 Docker 映像 ID。新版只接受合併後由交付端核對、固定在成品內的前版 ID，並交叉核對原先密封的授權內容及其摘要。來源環境變數、外部掛載或只改同一份授權內容，不能指定前版。成品沒固定前版即拒絕；拒絕時印出固定、可定位、不含私密欄位的原因。

## 解決了什麼
PR #11 GitHub 回放及出貨封裝皆成功，但真機合併後準備啟動時，原程式只接受早已不用的前版指紋，拒絕目前驗證過的現役版本。修正使以後每次都核對實際前版，而不是硬改新常數。新測試使用不同的兩個正確前版，並驗錯前版、沒綁定、摘要不符、過期均拒絕。

## 尚未解決或未驗證
此修正送 GitHub CI；只有新 PR 的最新提交全綠才能合併，之後才會重新使用對應的 Docker 成品驗同一模擬帳本和真實 Dry Run。舊容器未因此停止。

## 保留項目與驗證
保留原 OPG 資料、原合約清單、帳本唯一寫入者、時間窗、一次性驗證、無實盤且不下單。GitHub 實際候選 Docker 內執行前版驗收；既有空白／過舊、原策略、入口、錯誤掛載的檢查仍必跑。Mac 只做全綠合併後交付，不回填手動綠燈。

首輪 GitHub 成品已打出但合格範例被拒絕，尚未跑到原生矩陣。補上固定分類的拒絕原因，讓 Actions 分出缺前版、摘要不符、授權欄位和過期，而不是只顯示通過／失敗。任何拒絕仍禁止啟動，不印授權原文或實際帳本內容。
