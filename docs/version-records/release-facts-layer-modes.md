# C11：部署映像可讀性回歸

## 基於哪一版
3be8c6b171b1d2ae7885bae3c0cb57a4ac372b93

對應 PR #34。

## 改了什麼
把原有會驗雜湊、設定資料夾 0755／收據 0444 的工具接成 CI 和 Mac CD 共用的封裝入口。加入實際成品負例：在 077 私有工作目錄複製原始位元，檔案存在且雜湊一致，Docker 用 UID 1000 卻必須因權限拒絕；正常成品必須由同 UID 讀到完整八份證據。

## 解決了什麼
#34 首次 Mac 部署預檢曾把路徑權限拒絕回報為 `C11_RELEASE_FILE_MISSING`。已用原工具重新封裝，正確版本通過預檢後才切換。把這件事變成 GitHub Actions 必跑的回歸，不再靠部署現場撞到。

## 尚未解決或未驗證
本改動不涉及策略行為、候選行情、帳本或模擬成交。PR 最新提交仍須由 Actions 驗證。

## 測試
用實際 ARM64 候選映像驗真讀、缺檔、損毀及「檔案存在但 UID 1000 不可讀」。後者須確認內部例外是權限錯誤，不得用一般缺檔用例替代。

## 部署驗收
只改 CI／部署輔助入口，不變更 Worker 位元、事件或運行中的帳本。下一次組裝部署映像與回退映像都必須用同一個入口，再讀回實際成品。

## 保留項目與驗證
保留既有策略、行情來源、候選授權、模擬帳本、同輪整鏈回歸及實際部署門檻。
