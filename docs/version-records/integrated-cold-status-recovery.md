## 改了什麼
同一收盤的資料可讀時間由原生 Worker 實際驗證寫入，不用候選收到時間或 HTTP 下載完成時間代替。交接時重新核對仍合格的正式名單、K 線、原狀態與可讀時間；早於舊名單截止但已認證換代時，也可交給原策略即時判斷。若資料已齊，不因重新交接重抓。原收盤作價、防護與模擬帳本規則不變。近期自動補抓模式明確封入候選映像；原先已審核的封存來源不丟棄。新模式只在確有取數請求但回執不足時試官方封存，沒發出請求或合法限流不是外部斷線。封存只寫已驗證的原始 1m 缺口，不掃上市日期也不因此授權策略。

整合三項回歸：過了原「近期上市」界線仍能由已驗完整本機原始行情重建；按時間缺口與實際配額平行請求；續接 RPD 與兩種 ATR。自動公開封存不以累計檔數或位元組停止，在每個短批次驗證完整檔、保留進度後續跑；不放寬釘選審核來源、單檔安全或資料完整性。已獲原授權的歷史行情收到後，與當下名單效期分開記錄，只寫到同一已驗證合約資料；新請求和策略判斷仍要當下合格。測舊幣完整、少一根、網路不必要而不觸發、後段早到、相交去重以及原斷點順序。另同輪送兩個不同缺口的候選，在同一共享預算下交錯派發，短缺口不等長缺口完成。保留行情超過 260 根 15m 時改按區塊投影、跨塊續算同一個原狀態，不把讀取區塊大小當重建上限；缺少接縫的 1m 仍拒絕。移除候選輪替時備援佇列的 64 筆拒收條件。不同現行候選的封存準備互不阻塞，仍依真實退避共同收斂；已完成結果只由原單一擁有者核對後寫入。行情補資料不再套用交易判斷路徑專用的固定 1,200 預留，按當期外部上限、已用權重、排隊及實際已預留保護計算。已有連續完整 1m 時只在本機重建缺少的合成 K，不重抓整段，保留原已核對的列並接著更新 RPD 和兩種 ATR。

## 解決了什麼
移除已驗證資料的上市新舊門檻、同幣一次只能一段的硬限制，以及原歷史續接只更新 RPD 沒續 ATR。保留原續接證明、實際資料時鐘與獨立的正式名單效期。

## 尚未解決或未驗證
獨立驗證不能代替同一映像的完整 GitHub Actions 原生回放，也不能代替 Mac Docker 的真實 Dry Run。沒有可驗證的歷史時不得偽造可用狀態；仍有效的原計算 checkpoint 不覆蓋。不得只看檔案或把有呼叫當作有讀資料、完成判斷。

## 測試
合併內容須包含七個獨立驗證來源：#27 同輪換榜與實際策略讀取、#28 本機資料已齊的空白狀態、#29 缺單根不重抓、#30 無法承接的舊狀態、#31 重建後再遇缺口的續算、#32 有實際缺口才驗官方封存且只取已封存 UTC 日期、#33 曾確實續算的舊狀態有長斷層時比較真正缺口，不靠年份分類。完整整合候選另外對空白、不可續接兩種狀態故意挖掉一根，並於同輪加入新名單；需要跑原生封裝以證明同一候選真讀取並只判斷一次。預設不以候選量、上市日、回放等待或交易結果作為資料證明。最新整合候選尚未在 Actions 跑完。
原生封裝對同一個收盤測：舊名單先失效再更新，以及舊名單尚未到期已被更新取代。兩種都要求實際輸入讀取、一次原策略呼叫、原訊號／濾網結果、未多抓同幣、未下單。E+62 秒案例已在 ad8d41a 的 GitHub Actions 46110738420 通過，不能當作當前較新提交全綠。另保留既有多幣並行與封存回歸。
